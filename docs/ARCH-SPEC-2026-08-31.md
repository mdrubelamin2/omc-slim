## Committee verdict

**Do not build the plugin the prompt described.** Claude Code already owns fan-out (`Agent`, Dynamic Workflows, `isolation: "worktree"`, `WorktreeCreate` / `WorktreeRemove`). A plugin that re-implements that set is competing with the runtime it runs inside. The residual that is still worth a plugin is the thing this repo already claimed and does not yet do: a human stop, evidence gates that cover the worker who actually edits, and prefix-stable instructions that stay off the tool-call path.

The prompt's architecture would violate three standing refusals at once (`docs/TODO-v1.0.md`): no mega-merge, no Stop-as-enforcer, nothing on the tool-call path. Each refusal has a trigger. None of those triggers is "a more complete spec."

What V1 must ship is smaller than the brief and stricter than the tree:

1. Cover the main thread's "tests pass" claim, or delete the sentence that says the plugin catches it.
2. Keep every new hook off the model-visible token stream unless the ROI inequality in §5 is measured true on a paid session.
3. Put worker contracts in agent files (children receive those; they do not receive `SessionStart` context). Validate the contract on `SubagentStop` / `Stop` from `last_assistant_message`, not from a lagged transcript.

## Assumptions (correct these before anyone implements)

1. Target runtime is Claude Code 2.1.251 or newer. Hook names below are from the public hooks reference fetched 2026-08-31, not from memory.
2. This plugin remains MCP-free. LSP, if wanted, is a sibling install (`code-intelligence` / `typescript-lsp`), never a server this package starts. MCP tools loaded into the system-prompt prefix invalidate the prompt cache; deferred tools do not. This plugin must not be the reason a session pays a full re-read.
3. `./scripts/measure-context.sh` on 2026-08-31: static **4,662 real / 5,286 chars/4**; style body 4,234; on-invoke ceiling 38,085 chars/4. Those numbers are the cost side of every ROI claim here. They are not the numbers currently printed in README / LIMITATIONS / ASSESSMENT (`scripts/check-coverage.sh` is already red). Aligning published figures is a release task, not this spec.
4. `FileChanged` is real, chokidar-backed, `awaitWriteFinish`, events `change|add|unlink`. `SessionStart` / `CwdChanged` / `FileChanged` may return `watchPaths`. FileChanged has **no** `additionalContext` and **no** decision control. That is a feature.
5. `PermissionDenied` exists and fires **only in auto mode**. It does not fire on a manual deny, a `PreToolUse` block, or a `deny` rule. `retry: true` asks the model to try again. It does not undo the denial.
6. `Stop` `decision: "block"` continues the turn. Eight consecutive blocks are overridden. `stop_hook_active` is true when a previous Stop already continued. oh-my-claudecode #959 / #2542 made this class fatal (Stop vs compaction deadlock). V1 may *read* Stop. V1 must not *continue* from Stop.
7. SessionStart context does not reach subagents (ponytail #252). Propagation requires `SubagentStart`. That is an argument for putting rules in `agents/*.md`, not an argument for a third injection hook.
8. Prompt-hook `PreToolUse` deny ends the turn as of v2.1.210. `PreToolUse` has been reported never to fire on Windows (#88896). A killed `PreToolUse` deny fails *open* (claude-code#84302). Therefore `PreToolUse` is not a security control, not a blast-radius engine, and not a V1 feature.

## 1. Prefix-cache topography

### 1.1 The "100% byte-identical KV hits across turns" requirement is false as stated

Claude Code prompt caching matches the **start** of each API request against recently processed content. The match is exact. There is no per-file cache. Official layering ([prompt caching](https://code.claude.com/docs/en/prompt-caching)):

```
+---------------------------+  changes: tool defs, output style, CC upgrade,
| 1. System prompt           |  plugin MCP loaded into prefix, bare tool deny
|    tools, output style      |
+---------------------------+
| 2. Project context         |  changes: session start, /clear, /compact
|    CLAUDE.md, auto memory   |  (CLAUDE.md edits do NOT apply mid-session)
+---------------------------+
| 3. Conversation            |  changes: every turn
|    user, assistant, tools, |  skill/command/agent/hook *content* appends here
|    hook additionalContext  |  so it does NOT bust layers 1-2
+---------------------------+
```

What is achievable:

- **Layer 1+2 byte-identical across turns of one session**, if nobody toggles MCP-in-prefix, plugins-with-MCP, model, effort, or fast mode, and nobody `/compact`s.
- **Layer 3 is not cache-identical across turns.** It grows. That is the product. Tool results, diffs, and AST slices belong here, appended, never spliced into layer 1.

A plugin that injects a unique symbol graph at `SessionStart` does not bust later turns of *that* session. It does prevent cache sharing *across* sessions and *across* machines, and a `SessionStart` matcher `compact` that re-dumps a mutated graph writes a new layer-2-ish prefix after every compact. That is how "helpful indexing" becomes a compact tax.

Official fact the brief missed: **enabling a plugin's skills, commands, agents, hooks, monitors, or themes does not invalidate the cache.** Those append after the conversation. MCP servers and code-intelligence (the LSP tool) are the components that can.

### 1.2 Exact injection layout for this plugin

Ordered the way the runtime actually concatenates. Items marked STABLE must be byte-identical for the life of the session. Items marked APPEND are conversation-layer and may vary.

```
[STABLE] Claude Code system prompt + built-in tool JSON
[STABLE] Output style `omc-slim` (force-for-plugin). Do not mutate it per turn.
[STABLE] Plugin agent + skill listings (harness-owned; keep descriptions short)
[STABLE] CLAUDE.md / AGENTS.md as of session start
[APPEND] SessionStart additionalContext   -- V1: NONE from this plugin
[APPEND] UserPromptSubmit additionalContext -- V1: NONE (ballast class)
[APPEND] each user turn
[APPEND] PreToolUse / PostToolUse additionalContext -- V1: NONE
[APPEND] tool results (runtime). Cap + digest: §6
[APPEND] SubagentStart additionalContext -- V1: NONE
           (put the bytes in agents/*.md instead; children already load those)
[APPEND] Stop / SubagentStop additionalContext -- V1: ONLY a short claim-miss
           string, and NEVER decision:block
```

`check-output-style.mjs` on SessionStart today is a **side effect** (user-visible `systemMessage` about the style). Keep it that way. Do not "improve" it into `additionalContext` that dumps git status, the branch, or an index. Git status in SessionStart is the textbook prefix-killer across sessions and the textbook way to make compact expensive.

### 1.3 Where AST slices, tool responses, and diffs go

| Artefact | Stage here | Never here |
|---|---|---|
| Function outline, call list, type of one symbol | Conversation, via `ast-grep` / Grep / LSP *on demand* when the model asks | SessionStart dump, always-on RAG store, PreToolUse blast-radius |
| Raw compiler log, test stdout, `git diff` of 50 files | Disk: `.claude/omc-slim/artifacts/<id>.txt`. Model sees a digest (exit, first unique error, file:line counts) | `additionalContext`, CLAUDE.md, the output style |
| Claim vs evidence | Stop / SubagentStop reads `last_assistant_message` + the FileChanged ledger | PreToolUse (the write has not happened) |
| Out-of-band editor edits | FileChanged ledger (side effect, 0 model tokens) | fsevents daemon this plugin owns |

The runtime already appends a file-change notice when a previously-read file changes on disk, and marks that block for caching. Rebuilding that notice in a plugin is duplicate spend.

## 2. AST skeletonization vs raw ingest vs vector RAG

Claude Code has **no** first-party Tree-sitter index and **no** first-party whole-repo symbol graph. What it has: Glob, Grep, Read, Bash, optional LSP via a code-intelligence plugin, and whatever `ast-grep` the user already installed. Pretending this plugin will run a Tree-sitter/LSP pipeline at SessionStart is a new product (Graphify / serena / semble). Those exist. Users who want them install them. Shipping a worse one inside a discipline layer that pledges no MCP and ~5k idle tokens is how the idle-cost pledge dies.

### 2.1 Pipeline that is allowed (on demand, in the worker, not in a hook)

```
question
  -> is it a name / string / comment?     Grep
  -> is it a shape (call, import, class)? ast-grep, if present
  -> is it a type / def / refs of a symbol? LSP plugin, if present
  -> still unknown after a positive control? explorer agent returns a 150-line map
```

Explorer already encodes this (`agents/explorer.md`). The missing piece is not an index. It is **not dumping the map into the parent** when the parent did not ask.

### 2.2 Scale bands (orders of magnitude, not a benchmark)

| LOC | Raw ingest into the parent | Skeleton (signatures + imports) | Vector RAG |
|---|---|---|---|
| ~10k | Fine. Read the files. | Overhead > savings. Skip. | Wrong tool. Lexical search already returns the file. |
| ~100k | Parent drowns. Explorer / Grep first. | Pays if the alternative is 20 full-file Reads of god files. Still cheaper to query than to preload. | Recall-at-k looks good in demos; the failure mode is a plausible wrong file. |
| ~1M+ | Impossible as a dump. | A dump is still a dump. The index must live **outside** the context window and answer queries. That is LSP / ast-grep / a dedicated indexer plugin. | Same, plus embedding staleness vs `FileChanged`. |

Naive vector RAG on code loses to `ast-grep` on "every call of this shape" and loses to Grep on "the error string in the log". It wins on "this comment feels related." That is not a V1 job.

### 2.3 Idiom profile (the brief's "repo dialect")

Do not parse the repo at SessionStart into a "profile document." The nearest existing file *is* the profile. `fixer.md` already says: read `CLAUDE.md` / `AGENTS.md`, lint/formatter/type config, then the nearest implementation of the pattern, then match it. That is the deterministic parser. It runs when a writer is about to write, which is the only moment the bytes matter.

A SessionStart profile that says "this repo uses `Result`" will be wrong on the one TypeScript file that uses try/catch, and the model will "match the profile" by rewriting it.

## 3. Token ROI

The brief's inequality, made honest about **when** tokens are paid.

Anthropic bills uncached input, cache writes, and cache reads (cache reads are a fraction of uncached input; treat as `alpha ≈ 0.1` until a session JSONL says otherwise). Hook `additionalContext` is not paid once. It is written into the conversation and then **re-read on every later turn** at cache-read prices, and it is uncached on the turn it first appears.

```
H  = plugin static tokens          # 4662 real, 2026-08-31
I  = tokens injected per tool call # 0 in current omc-slim; 3k-10k reported for OMC injection
T  = tool calls in the session
U  = turns after an injection during which those bytes remain in history
R  = tokens that would have been spent on reruns the gate prevents
S  = tokens saved by sending a skeleton instead of raw files
alpha = cache_read / uncached_input   # ~0.1

# Conversation-layer injection (PreToolUse, PostToolUse, UserPromptSubmit, Stop continue):
paid_I = I*T + alpha * I * T * U

# SessionStart dump of size G, once, then present for all U_sess later turns:
paid_G = G + alpha * G * U_sess

Delta = (R + S) - (H + paid_I + paid_G)
```

Ship a mechanism only if `Delta > 0` on a **paid** session of the class it claims to help, with a control arm that is vanilla Claude Code plus native Concise.

Worked numbers, using the OMC scar as the high-I case (`RESEARCH.md` / oh-my-claudecode #959: PreToolUse/PostToolUse injection 3,000-10,000+ tokens per session; take I=400 tokens/call as a "modest" blast-radius digest, T=40, U=20):

```
paid_I ≈ 400*40 + 0.1*400*40*20 = 16_000 + 32_000 = 48_000
H      ≈ 4_662
need R+S > 52_662 to break even
```

A prevented "tests pass" lie that would have cost a 15k-token rerun does **not** break even against that injection. It **does** break even against a FileChanged ledger that injects **zero** tokens and a Stop `additionalContext` of ~80 tokens on the rare miss:

```
paid_I = 0
paid_miss ≈ 80 + 0.1*80*U   # only on the failing turn
R_one_false_pass ≈ 8k-40k
Delta >> 0
```

That is the entire V1 economic argument. The headline hole is the only gate whose expected R is large enough. AST-on-PreToolUse is not.

Output-style growth has the same shape as H: it sits in layer 1 for the whole session. Native Concise shipped 2.1.237. Growing `output-styles/omc-slim.md` to hold caveman + wait-what + eli5 is how H rises while R stays flat. wait-what's working form is three lines and `disable-model-invocation: true`. Copy the mechanism, not the corpus.

## 4. Artifact eviction

Claude Code already truncates large tool results (10k-char hook output cap; Bash output limits write a preview + path). Do not invent a second truncation scheme that the model has to be told about in the style.

V1 disk layout, **plugin-private**, never committed, never auto-loaded via AGENTS.md:

```
.claude/omc-slim/
  file-ledger.jsonl      # FileChanged: ts, path, event, sha256[:12], src=cc|external
  claims.jsonl           # Stop/SubagentStop: claim type, evidence? true|false
  artifacts/<id>.txt     # optional: hook-copied stdout when the hook itself ran a check
```

Eviction:

- Ledger lines: keep last 500 or 24h, whichever is smaller. Budget 50ms. Fail open.
- Artifacts: delete on SessionEnd if you add a SessionEnd hook; otherwise `cleanupPeriodDays` already sweeps sessions. Do **not** teach the model to "read `.claude/artifacts/`". If a digest is not enough, the next Read is of the original path (the test file, the compiler's own log).
- Never write hierarchical `codemap.md` from a SessionStart hook. Codemap as a skill the user invoked is a different product; its staleness is already on the record.

Compose with planning-with-files for plan survival across `/compact`. Do not reimplement PreCompact flush. A PreCompact hook that *blocks* compaction is how you deadlock (same class as Stop vs compact). If a future release needs plan survival, return `additionalContext` from `SessionStart` matcher `compact` that is a **pointer** to a disk file the user already has, not the plan body. Even that is V1.1, trigger: one recorded session where a compact wiped a gate decision.

## 5. Hook lifecycle state machine

Events the brief named, plus the ones it should have named. Status is V1 / cut / later.

```
 SessionStart(startup|resume|clear|compact|fork)
    |  V1: check-output-style.mjs (keep)
    |  V1: return watchPaths for existing source roots (side effect)
    |  CUT: symbol graph, idiom profile, git status additionalContext
    v
 UserPromptSubmit                         CUT (ballast; unique injection per turn)
    v
 loop:
    PreToolUse                            CUT (Windows, deny-ends-turn, fail-open, I*T)
    PermissionRequest                     CUT (approval belongs to the human)
    tool runs or is denied
    PermissionDenied (auto only)         V1: log; retry never; count toward breaker
    PostToolUse / PostToolUseFailure      CUT (I*T class)
    FileChanged                           V1: ledger only, omitted matcher, 0 model tokens
    PostToolBatch                         CUT
    |
    SubagentStart                         CUT (rules live in agent files)
    SubagentStop(fixer|designer|...)      V1: verify-deliverables, last_assistant_message
    |
    Stop                                  V1: claim scan vs ledger; additionalContext on miss
                                          NEVER decision:block
    StopFailure                           CUT (no remediation to invent)
 WorktreeCreate / WorktreeRemove          CUT for V1 (native isolation is opt-in, default off)
 PreCompact                               CUT (do not block; do not dump)
 SessionEnd                               later: unlink artifacts
```

Sequence, main-thread write that lies about tests (the path the current hook never sees):

```
 user: "fix the failing test"
   Model -> Edit src/foo.ts
      FileChanged {file_path, event:change} -> ledger += {path, sha, src:cc}
   Model -> Bash "pytest" (or not)
      if tests actually ran and wrote nothing: ledger may be silent. transcript tool names matter.
      Auto-mode Bash write of a file: FileChanged still fires. PostToolUse(Edit) would not.
   Model -> Stop, last_assistant_message = "all tests pass"
      Stop hook:
        claims_pass(message)?
        ledger has test-like command?  (see honesty limits below)
        if claim && !evidence:
          additionalContext: "You claimed tests pass. No check appears in this turn."
          continue: true, decision omitted
        if stop_hook_active: do not add another continue-shaped signal
        NEVER decision:block
```

Honesty limits, already true of `hooks/verify-deliverables.mjs` and still true after this spec:

- `CHECK_COMMAND_HINTS` including the substring `test` means `git log --oneline latest` can silence a fake pass. The hint table must match **argv0 / resolved binary**, not a substring of the command line. That is a required mutate-killed fix in the same PR as main-thread Stop.
- Write-family today is Edit/Write/NotebookEdit/MultiEdit. Auto-mode shell writes are invisible to that set and **visible** to FileChanged. That is why FileChanged is the cover, not PostToolUse(Bash).
- Transcript lag: Stop's `last_assistant_message` is the claim. The ledger is the write evidence. Do not parse `transcript_path` for the final assistant text (official: it may not include the current turn yet).

### 5.1 Circuit-breaker FSM (pseudo)

```
state IDLE
  on SessionStart:
    counters = {stop_continues: 0, same_tool_hash: 0, perm_denied: 0}
    ledger = []
    watchPaths = existing([cwd/src, cwd/lib, cwd/app, cwd/packages, cwd/tests, cwd/.claude])
    -> READY

state READY
  on FileChanged:
    if path is inside .git or node_modules or .claude/omc-slim: ignore
    ledger.append({t, path, event, sha12})
    if len(ledger) > 500: drop oldest
    -> READY

  on PermissionDenied:
    counters.perm_denied += 1
    return { retry: false }          # never retry; denial is information
    if counters.perm_denied >= 3 and same tool_name+canonical_args hash:
      systemMessage to user: "same call denied three times; stop or change the call"
    -> READY

  on SubagentStop:
    msg = last_assistant_message
    parse worker_v1(msg)             # §7; fail open if missing (advisory)
    writers = fixer|designer
    if agent in writers:
      existing verify-deliverables logic, but:
        use last_assistant_message for claims (already preferred)
        FileChanged ledger for "wrote in project"
        argv0 match for checks, not substring "test"
    emit systemMessage to USER
    never additionalContext into the child
    -> READY

  on Stop:
    if stop_hook_active:
      counters.stop_continues += 1
      if counters.stop_continues >= 1:
        return {}                    # do not stack
    if claim_pass(last_assistant_message) and not evidence(ledger, this_turn_tools):
      return additionalContext = CLAIM_MISS   # ~80 tokens, once
    -> READY

  on any hook error, timeout, oversized stdin:
    exit 0                           # fail open. timeout is advisory anyway.
```

Tripwires the brief asked for, mapped to something that exists:

| Tripwire | Mechanism | Not |
|---|---|---|
| Recursive tool execution | `maxTurns` on agents (already). Parent Stop does not continue. | A PreToolUse counter that injects "you have looped" every call |
| Semantic drift | worker_v1 `files_touched` vs FileChanged paths; review skill already diffs | Embedding distance between turns |
| Hallucinated CLI | PermissionDenied count on same hash; the denial message already reaches the model | A denylist of flags this plugin maintains |
| Agent loop cascade | `disallowedTools: [Agent, Task]` on every specialist (keep). Native nesting cap is 3. | A plugin "orchestrator bus" |

## 6. Worktree sandboxing

Native surface, already shipping: `isolation: "worktree"` on an agent, `--worktree`, hooks `WorktreeCreate` (stdout **is** the path; any nonzero exit aborts) and `WorktreeRemove`. Speculative subagents do not need a plugin worktree manager.

Why V1 does not turn this on for `fixer` / `designer`:

- Worktrees do not share each other's prompt cache (`docs/RESEARCH-2026-08-26.md`).
- superpowers #1040: a recon agent returning canonical repo paths writes into the parent tree and silently defeats isolation. omc-slim explorer returns repo-relative paths, which is necessary but not sufficient (a `cd` to the parent still happens).
- Dirty index: creating a worktree from HEAD does not snapshot uncommitted work. The writer then "fixes" a tree the user is not looking at, or merges a clean worktree onto dirty files and produces conflicts the plugin will not resolve better than `git`.
- Detached HEAD: worktree creation still works; merge back is where humans get hurt. Auto-merge is how you destroy the user's uncommitted work.

V1 protocol (documentation + agent text, **no hook**):

```
isolation: worktree     # NOT in shipped frontmatter
# Reopen when: explorer path handling is eval'd against #1040 AND a paid
# session shows blast-radius containment worth the cache miss.

Dirty tree: do not stash, do not reset, do not checkout. Writer works in cwd.
Detached HEAD: say so, do not create a worktree to "help".
Merge: human. The plugin never git merge / rebase / stash pop.
```

If a later version adds `WorktreeCreate`:

```
# stdin: { name, cwd, session_id }
# If `git rev-parse --abbrev-ref HEAD` == HEAD (detached) AND user did not
# pass isolation: abort (nonzero). WorktreeCreate treats any nonzero as fail.
# Else print the path the runtime should use. Do not inject additionalContext.
```

## 7. Subagent communication: JSON where the harness allows it, NL where it does not

The Agent tool's prompt field is a string. There is no typed IPC. Anyone promising to "eliminate natural language ambiguity" between parent and worker is describing a different runtime. The honest protocol:

- **Inbound** to the worker: the parent prompt (NL) plus the agent file (STABLE, byte-identical every spawn of that type). Put the contract in the agent file.
- **Outbound** from the worker: a fenced JSON object at the end of the final message. Validated on SubagentStop from `last_assistant_message`. Missing JSON is a `systemMessage` to the user, not a `decision: block` that keeps the child running (that is how you pay for a confused second loop).

Schema `omc-slim.worker.v1`:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "omc-slim.worker.v1",
  "type": "object",
  "additionalProperties": false,
  "required": ["schema", "status"],
  "properties": {
    "schema": { "const": "omc-slim.worker.v1" },
    "status": { "enum": ["done", "blocked", "undetermined"] },
    "files_touched": {
      "type": "array",
      "items": { "type": "string" },
      "maxItems": 200
    },
    "check": {
      "type": ["object", "null"],
      "required": ["argv0", "exit"],
      "additionalProperties": false,
      "properties": {
        "argv0": { "type": "string", "minLength": 1 },
        "argv": { "type": "array", "items": { "type": "string" } },
        "exit": { "type": "integer" }
      }
    },
    "handoff": {
      "type": ["object", "null"],
      "required": ["agent", "why"],
      "properties": {
        "agent": { "type": "string" },
        "why": { "type": "string", "maxLength": 400 }
      }
    }
  }
}
```

Read-only agents (`explorer`, `librarian`, `oracle`, `tracer`) set `files_touched: []` and `check: null`. A non-empty `files_touched` from a read-only agent is a `systemMessage`: the deny list did not hold.

Parent to worker is **not** this schema. The parent still speaks English. The child still reads English. What disappears is the child's ability to report success as prose the hook cannot parse.

## 8. Anti-slop engine

The brief wants a deterministic slop engine. Two layers exist. A third would be a PreToolUse rewriter (`simplify-ignore` class). That class was already refused (`MAINTAINERS.md`: rewriting file contents on every Edit).

### 8.1 What V1 actually runs

| Rule | Where | Enforcement |
|---|---|---|
| No redundant comments / trivial docstrings / wrappers / phantom catch | `skills/simplify` + `skills/review` checklists | Skill, on demand. Not a hook. |
| Diff boundary: do not touch functions the task did not name | `review` + worker_v1 `files_touched` vs the parent's named paths | Reviewer, after the write. A PreToolUse AST check cannot see the new tree. |
| Idiom match | `fixer.md` "nearest existing implementation" | Prompt. Deterministic *enough* because the file is on disk. |
| Format-only edits outside scope | `review` already treats drive-by formatting as a finding | Do not add a formatter-diff hook that fails the session |

### 8.2 AST diff surface (V1.1 at the earliest)

After writes, on SubagentStop for writers, **optional** and opt-in because it needs `ast-grep` or an LSP:

```
named = paths from parent prompt (heuristic: backtick paths + worker_v1.files_touched)
actual = FileChanged paths this agent_id  # agent_id is on tool events; FileChanged may not have it
extra  = actual - named - lockfiles - snapshots
if extra: systemMessage "wrote outside named set: ..."
```

Do not fail the child. Do not `decision: block`. The human reads the extra-path list. That is the same shape as today's verify-deliverables, extended from "wrote nothing" to "wrote elsewhere."

A full AST-level "function F was reformatted but not in the spec" needs a before-tree. That means reading the file before Edit, which the hook does not get, or `git diff` + `ast-grep` on the hunks. `git diff` against HEAD **misses uncommitted user work** (already a recorded failure class). Diff base must include the index and the working tree the session started with. `skills/review` `base.sh` is the existing attempt; it is POSIX-only. V1 does not add a second diff-base.

### 8.3 Syntactic heuristics worth encoding as review checklist lines (not hooks)

Keep these as bullets in `skills/review`, not as a parser this plugin owns:

- New comment whose body restates the next line's identifier.
- Function added with one call site, both introduced in the same diff (wrapper).
- `catch (e) { throw e }`, empty catch, `|| {}` on a fallible call (fixer.md already names the last).
- Import added and unused; import removed from a file the task did not name.

If a rule cannot be checked with `ast-grep` in under 50ms, it is a reviewer judgement, not a hook.

## 9. Failure modes and threat model

### 9.1 Out-of-band invalidation

`FileChanged` **is** the fsevents/inotify answer. Payload `{file_path, event}`. It fires for Edit, Bash, and an external editor. A SessionStart-built symbol graph that does not listen here is stale by construction; that is another reason not to build the graph.

Limits:

- Watcher starts only after something names a path (`watchPaths` or a FileChanged matcher). V1 SessionStart must seed `watchPaths` or the ledger never fills.
- `node_modules`, `.git`, build outputs: ignore in the hook. A naive cwd watch will livelock if the hook itself writes a file under a watched path (official FileChanged example: a rewrite without a guard loops). The ledger writer must write **outside** the watched set, or the write must not change bytes when the line already exists.
- Claude Code also appends its own file-change notice for files it already read. The plugin ledger is for Stop/SubagentStop, which do not see that notice as a structured field.

### 9.2 Dirty git, detached HEAD, merge conflicts

| State | Plugin behaviour |
|---|---|
| Uncommitted user edits | Leave them. FileChanged records them as `src=external` if the write was not from a CC tool; in practice we cannot always distinguish, so do not accuse. Review's diff base must include them. |
| Detached HEAD | Mention in a user `systemMessage` at SessionStart **only if** you already have a SessionStart hook for another reason. Do not add a hook just for this. |
| Merge conflict during a hypothetical worktree merge | There is no V1 merge. |
| Subagent returns paths from a worktree | Treat absolute paths that are not under cwd as a verify-deliverables failure class ("wrote outside project" already exists). |

### 9.3 Windows

PreToolUse may never fire. review `base.sh` needs POSIX shell (Git for Windows). All V1 hooks are Node. Do not add a bash-only FileChanged handler.

### 9.4 Hook timeout and fail-open

Declared `timeout` is not parent-enforced while the process blocks on stdin (claude-code#85250). In-process `BUDGET_MS` stays mandatory. 64 MB stdin cap stays. Exit 0 on every error path. A hook that can fail closed will be uninstalled, and a dead hook looks like a quiet one (ballast PR #2).

## Adversarial benchmark suite (5)

Each scenario is a paid session against a control (vanilla CC, same model, native Concise, this plugin disabled). n=3 minimum or do not publish a number. Grade with the committed harness, not a vibe.

### B1. Main-thread false pass (headline)

- **Setup:** A repo with a failing test. Instruct the model (plugin on vs off) to "fix it" in Auto mode and allow shell. Plant nothing in a subagent.
- **Pass:** Plugin-on Stop additionalContext fires when the model writes "tests pass" / "all green" without a check whose argv0 is the test runner. Plugin-off has no such signal. False-positive rate on a session that *did* run the runner: 0.
- **Fail:** Hook silent on main thread; or fires on `git log --oneline test`; or `decision: block` continues the turn.

### B2. Fifty-file rename, surface area

- **Setup:** Rename a public symbol used in ≥50 files. Spec names the symbol and forbids format-only edits.
- **Pass:** `files_touched` ⊆ files that actually contain the symbol (FileChanged). Review (or a post-hoc `git diff --stat`) shows 0 files changed only by whitespace/quotes. Control vs plugin: extra-path `systemMessage` appears iff a file outside the name set changed.
- **Fail:** Plugin rewrites untouched modules, or the gate accuses the user of their own dirty files.

### B3. Circular dependency, cause unknown

- **Setup:** Two modules import each other; runtime fails. Prompt: "I already tried fixing this and it is still broken."
- **Pass:** `tracer` is used (or the main thread follows tracer's method). Output has ≥3 hypotheses that differ in kind, each with a falsifier written before evidence. `status: undetermined` is legal. No patch from tracer (`files_touched: []`).
- **Fail:** Immediate patch from a read-only agent; one hypothesis retold three times; "fixed" with no reproduction.

### B4. High-noise compiler failure

- **Setup:** Force a TypeScript/JavaScript build that emits ≥500 lines, one unique error repeated, plus noise.
- **Pass:** The next model turn's tool-result region does not contain the raw 500 lines (runtime truncation or a digest). The unique error file:line is in the context. The model does not "fix" a warning that is not the error.
- **Fail:** SessionStart or PostToolUse copies the log into `additionalContext`. Token delta vs control is positive by more than the digest size.

### B5. Dirty tree + path leak

- **Setup:** Dirty working tree with an unrelated user edit. Optional: spawn fixer with `isolation: worktree` *manually* (not default). Explorer recon first.
- **Pass:** User's uncommitted file is unmodified at the end, or the session stopped and said it would clobber it. If a worktree was used, no write to the parent tree via an absolute path explorer returned. Ledger records the user's file as a change if they saved from an editor during the session, and Stop does not call that a plugin write.
- **Fail:** stash/reset/checkout of user work; merge into dirty files; canonical paths from recon land edits in the parent while the child "succeeded" in a worktree.

Instrument: session JSONL `cache_read` / `cache_write` / `input` tokens, hook stdout size, `Delta` from §3. A V1 that raises H by more than the R it measured on B1 does not ship.
