# Dogfood receipt — 2026-08-29

Closes cross-cutting item 3 of the v1.0 backlog: *"one real session transcript
per release. Starts at R1, never stops."* This is the first one, and it is
written against a session that produced 22 commits and 7,883 inserted lines
across 54 files.

**What this is evidence of, and what it is not.** It is one session, run by the
plugin's own author-agent on the plugin's own repository, so it is the weakest
class of evidence in this project. It is recorded because the alternative is
nothing, and because the four standing refusals have reopening triggers that
nobody has ever been positioned to observe.

## What the hooks did

`verify-deliverables` fires on `SubagentStop` for `fixer` and `designer`. Six
fixer dispatches, **zero warnings surfaced.** Every one of them wrote files, so
silence is the correct output and this is a negative result: the hook did not
false-accuse across six real dispatches, which is the failure mode it was
rewritten twice this session to avoid.

It is not evidence the hook *catches* anything in production. No dispatch in this
session ended without a write, and none claimed a verification it had not run.

## What went wrong, recorded because it is the useful part

Three failures by the orchestrator, none of them caught by any gate:

1. **`git add -A` run twice while writer lanes were mid-edit.** Two lanes' work
   landed under commit messages describing something else. Both lanes noticed and
   said so; neither lost work. The defect is mine, and the mechanism that should
   have prevented it — the preflight conflict scan — was run once at the start
   and never extended when lanes were added mid-session.
2. **A gate exploit test that proved nothing.** I ran the full coverage gate to
   check a new assertion while a concurrent lane was editing a file the token
   ceiling derives from. The gate exited early on a stale figure, my greps
   matched nothing, and I read that as "the exploit does not fire" — the exact
   false-clean-result failure `explorer`'s positive-control rule exists to
   prevent, committed by the orchestrator that ships the rule. Caught only
   because the success line was also missing.
3. **A false claim written into the output style.** I added *"no hook sees which
   style won"* as justification for a new instruction, twenty minutes before a
   research lane returned evidence that a StatusLine hook reads exactly that.
   Corrected in the same session.

**All three are the same class: acting on an assumption instead of a check.** The
plugin has a rule against each one. Having the rule and being the thing that
breaks it is the most honest data in this file.

## What a reader should take from this

The register held: 22 commits, all with reasoning, none with a claim I did not
check. The delegation was real and useful — the five librarian runs produced
findings no amount of reasoning would have: that the moat sentence was false,
that `observer:` is in the binary, that a 500-task benchmark already exists.

And nine of twelve components did not fire in fourteen hours of hard use on this
repository. Both of those are true, and the second one is the one that should
drive the next release.
